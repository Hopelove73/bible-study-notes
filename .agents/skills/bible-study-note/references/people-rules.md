# 人物规则 · People Rules

> 人物卡不是「本章出现的人名表」。它是**消歧工具 + 记忆锚点**。

## 1. 数据结构

`assets/people.js` 必须是 JSON 兼容的 JS（键名加双引号），这样浏览器和校验脚本都能读：

```js
window.PEOPLE = [
  {
    "id": "peter",
    "name": "西门（彼得）",
    "aka": ["彼得", "矶法", "西门巴约拿"],
    "star": 1,
    "role": "渔夫 · 十二使徒之首",
    "relation": "约拿的儿子，安得烈的兄弟；已婚，岳母住在迦百农",
    "first": "可1:16",
    "key": ["可1:16-18", "可8:29", "可14:66-72"],
    "one": "被耶稣改名「石头」，却三次不认主；复活后被重新托付。",
    "avoid": "不要与「奋锐党西门」「长大麻风的西门」「行邪术的西门」混淆。",
    "tags": ["新约", "使徒", "核心"],
    "chapters": ["mark-01", "mark-03"]
  }
]
```

| 字段 | 要求 |
|---|---|
| `id` | 全局唯一，小写英文 + 连字符。同一个人跨章复用同一个 id |
| `name` | 显示名。重名时必须加括号限定：「约翰（施洗者）」「约翰（西庇太的儿子）」 |
| `aka` | 别名、称号、希腊文名。没有就给空数组 |
| `star` | 1 / 2 / 3，见 §2 |
| `role` | 12 字以内，身份 + 作用 |
| `relation` | 亲属、师承、敌对关系，一行讲清 |
| `first` | 首次出现（书卷缩写 + 章:节） |
| `key` | 2–4 处关键经节 |
| `one` | 一句话记住他（≤60 字），要有张力，不要履历 |
| `avoid` | 最容易混的地方。**这是人物卡最有价值的一栏** |
| `tags` | 2–4 个：约 / 体裁 / 身份 |
| `chapters` | 出现过的章节 id 数组，按时间顺序追加 |

## 2. 星级

| 星 | 含义 | 每章数量 | 判定 |
|---|---|---|---|
| ★★★ | 必记 | **恰好 3** | 主角 + 本章关键对话者 + 改变剧情的人 |
| ★★ | 知道作用 | 不限 | 有台词或有行动，但非本章核心 |
| ★ | 仅提及 | 不限 | 只出现在名单、家谱、地名里 |

**硬规则**：
- 每章 `star: 1` 恰好 3 位。多一个或少一个都算 P0。
- 同一个人在不同章可以升星：在可 1 是 ★★★ 的彼得，在可 5 可能只是 ★★。`star` 是**本章权重**，不是人物总评。
- 不要把「耶稣」永远自动给 ★★★。如果某章他几乎不在场（如以斯帖记），就不该硬塞。

## 3. 收谁、不收谁

**收**：
- 有名有姓，且在本章说话或行动
- 无名但推动剧情（「患血漏的女人」「被抬来的瘫子」）——name 用描述性称呼
- 群体若作为单一角色出现（「法利赛人」「希律党人」「格拉森人」）可收，name 加「（群体）」

**不收**：
- 只在家谱里出现、本章无动作的人（放脚注，不进卡片）
- 地名、物件、动物
- 纯背景人物（「众人」「有人」）——除非本章只有他们

**特殊**：撒但、污鬼、天使可以收，但 `tags` 标 `灵界`，`star` 最高给 ★★，除非本章核心冲突就是灵界对抗。

## 4. 重名与别名

圣经里至少 6 个「西门」、5 个「马利亚」、4 个「雅各」、2 个「犹大」（使徒 + 耶稣的兄弟）、2 个「约翰」。

处理顺序：
1. **先查已有 id**：`grep '"name"' assets/people.js`
2. **同名不同人** → 新建 id，name 加括号限定：`西门（古利奈人）`
3. **同人不同名** → 复用 id，把新名字加进 `aka`
4. **不确定是不是同一人** → 宁可分成两条，在 `avoid` 里写「有争议，可能同一人」

**必须写进 `avoid` 的四组**：
- 施洗约翰 vs 西庇太的儿子约翰
- 西门彼得 vs 奋锐党西门 vs 古利奈人西门
- 犹大（加略人）vs 犹大（耶稣的兄弟）vs 犹大（巴撒巴）
- 马利亚（耶稣的母亲）vs 抹大拉的马利亚 vs 马大/马利亚姐妹

## 5. 追加流程

写完一章正文后：

1. 列出本章所有具名人物 + 无名关键角色
2. 对每一个：查 `people.js` 是否已有 id
3. 已有 → 只在 `chapters` 末尾追加本章 id；若本章戏份重，考虑升星
4. 没有 → 新建对象，按 §1 填满，`chapters` 只放本章 id
5. 数一遍 `star: 1` 是否恰好 3
6. 跑 `check_note.py`，它会校验 id 唯一、三星人数、章节引用

**不要**为了凑数把「众人」拆成三个人物卡。

## 6. 页面侧

- 章节页：`<div class="people-grid" id="chapterPeople" data-chapter="mark-02"></div>`，由 `app.js` 按 `chapters` 过滤渲染
- 总表页：`people.html` 读同一个数据源，提供搜索、星级筛选、翻转卡、易混对照、连线题
- 新增人物后**不需要**改 HTML，刷新即可
- 若新增了「易混组」，在 `people.html` 的对照区手动加一条

## 7. 质量检查

| 检查 | 不合格示例 |
|---|---|
| `one` 是不是一句话 | 「他是渔夫，后来跟从耶稣，成为使徒，写了彼得前书…」 |
| `avoid` 有没有具体指向 | 「注意不要搞混」 |
| `role` 有没有判断 | 「一个门徒」 |
| `relation` 有没有出处 | 「据说他是…」 |
| 星级是否本章权重 | 把只出现一次的人也标 ★★★ |
