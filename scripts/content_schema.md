# 章节内容 JSON 契约（build.py 用）

你**只写内容 JSON**，不写 HTML。结构、经文、导航、目录、标注、人物绑定全部由
`scripts/build.py` 生成——所以**绝对不要手写 HTML 文件、不要碰 people.js / index.html**。

## 文件位置

```
<书卷中文目录>/_src/<章节id>.json      例：阿摩司书/_src/amo-02.json
```

写完后自检（必须跑到 ✓ 才算交活）：

```
py scripts\build.py amo-02
```

它会逐字段报错，并给出每节字数还差多少。**只改它指出的字段，不要重写全文。**

## 顶层字段

| 字段 | 说明 |
|---|---|
| `id` | 必须与文件名一致，如 `amo-02` |
| `thesis` | 一句话主旨，60–100 字，放进封面 |
| `golden` | 金句引用，如 `2:17`（只写「章:节」，经文由脚本注入，**不要抄经文**） |
| `minutes` | 精读分钟数，25–40 |
| `genre` | 文体，如 `预言 · 审判宣告` / `叙事 · 古代传记` / `书信 · 论证` |
| `before` | 读前准备 |
| `bg` | 背景五格（历史/地理/文化/文学/救赎史） |
| `overview` | 章节概述 + 结构大纲 5–8 行 |
| `map` | 思维导图：3–6 支、3–10 个流程节点 |
| `segs` | 分段精读：**6–12 段，经文范围必须严丝合缝覆盖全章、不重不漏** |
| `key` | 重点经文 3–5 处，每处四步（上下文/字词/神学/应用） |
| `theology` | 关于神 / 关于人 / 关于基督 |
| `prayer` | 祷告 2–4 段 + 祷读提示 |
| `apply` | 本周一个行动 + 职场/家庭/教会三场景 + 可选辅助操练 |
| `tasks` | A/B/C/D 四组，共 8–12 个复选框 |
| `review` | 三道自测 + 背诵节 + 背法 + 下一章预告 |
| `refs` | 注释与背景的说明文字（三级标注表由脚本生成） |

```json
    "lead": "一句引导（100–150 字）",
    "rows": [["① 问题", "读的时候留意什么"], ["② …", "…"], ["③ …", "…"]],
    "position": ["<b>小标题</b>：说明", "<b>…</b>：…", "<b>…</b>：…"]
  },

  "bg": {"历史": ["段1", "段2"], "地理": ["…"], "文化": ["…"], "文学": ["…"], "救赎史": ["…"]},

  "overview": {
    "lead": "……",
    "paras": ["段1", "段2", "一句话概括：<b>……</b>"],

  "apply": {
    "act": "本周一个行动（具体到对象/时间/动作/可验证）",
    "scenes": [["职场", "……"], ["家庭", "……"], ["教会", "……"]],
    "notes": [["辅助操练一", "……"], ["辅助操练二", "……"]]
  },

  "tasks": {
    "A": ["观察任务", "…"],
    "B": ["记忆任务"],
    "C": ["关联任务", "…"],
    "D": ["输出任务", "…"]
  },

  "review": {
    "q": [["问题", "答案"], ["…", "…"], ["…", "…"]],
    "mem": "2:6",
    "how": "背法……",
    "next": "阿摩司书 3 章",
    "nextText": "下一章预告……"

```

## 硬规矩

1. **经文一个字都不要抄**：`scripture`、`blockquote`、背诵段全部由脚本从
   `verses/<id>.json` 注入。你只写节号（`2:4-6`）。抄错就是 A20 失败。
2. `segs` 的 `r` 必须**连续覆盖 1 到末节**：6–12 段，不许漏、不许重、不许跨章。
3. 每个 seg 必须有 `christ` 标注；有释经分歧时加 `warn` 标注，**并列呈现，不下裁判**。
4. 禁止句式：「神今天对你说」「主要你」「神绝不会让你」「只要相信就一定会」「家人们」等。
5. `notes` 的等级只有 `info` / `warn` / `christ`，emoji 由脚本加，**正文里不要再写 🟦🟨🟧**。
6. 不要在 JSON 里写 `TODO`、`??`、`{{}}`——会直接判失败。
7. `thesis` 与各段正文允许内联 `<b>`，不要用其他标签。

## 字数目标（这是唯一「越少越好」的地方）

按 **CJK 汉字** 计（脚本会算）：

| 节 | 目标 | 下限 | 上限 |
|---|---|---|---|
| before | 250 | 120 | 700 |
| bg | 900 | 600 | 1800 |
| overview | 500 | 250 | 900 |
| map | 350 | 80 | 900 |
| reading | 2650（含注入经文） | 2500 | 9500 |
| key | 700（含注入经文） | 500 | 2200 |
| theology | 600 | 250 | 1200 |
| prayer | 350 | 150 | 700 |
| apply | 650 | 300 | 1300 |
| tasks | 400 | 250 | 1200 |
| review | 500 | 200 | 900 |
| refs | 300 | 150 | 900 |
| **全章** | **7500–9000** | 4500 | 16000 |

写作密度：`segs[].p` 每段 200–500 字，**每段最多 3 段**；不要为凑字把段落压薄。
短章（如俄巴底亚、约翰二书）靠精读段落补足 `reading`，不要注水背景。

## 交活前

```
py scripts\build.py <id>     # 必须 ✓
```

报错就按提示改那个字段，再跑一次。全部 ✓ 后汇报：章节 id、字数、哪些地方标了 🟨 分歧。
